# Post-scan reveal contract and visual research

## Contract checklist

This checklist was written from the approved “Post-scan computation reveal” section of draft PR #28 before the reveal was wired into the production path.

- [x] A full-screen transition sits after accepted capture and before the reading.
- [x] The screen is driven by named production events: capture quality, eligible regions, personal-history comparison when eligible, and reflection assembly.
- [x] A personal-history stage is skipped for calibration runs rather than implied.
- [x] The visual field is an original, non-photographic schematic; it never receives a frame or landmark array.
- [x] Only eligible approved Qi Se regions are marked. Ineligible regions remain absent.
- [x] No 478-point mesh, fabricated progress percentage, countdown, stage duration or minimum display time is used.
- [x] The privacy line remains visible: “Working on this device · your face image is not being stored.”
- [x] Reduced motion changes region state without sequential reveal animation; status updates are named and bounded.
- [x] Error, abstention, cancellation, restart and background paths release transient capture material and return a useful action.
- [x] Browser screenshots and release audit evidence are recorded for the PR before review.

## Visual thesis

“Your reading taking shape from visible, bounded evidence.” The first viewport has one quiet instrument: a paper-like field, a short event ledger and the persistent privacy boundary. The field is deliberately schematic rather than a face likeness; the evidence is the sequence of completed work, not decorative machine theatre.

## Research references and boundaries

The references informed hierarchy, restraint, material contrast and evidence-shaped status. None is copied as an asset, layout or illustration.

| Source family | Reference | What was learned | What is not copied |
|---|---|---|---|
| Editorial / print | [M+ Library Special Collection](https://www.mplus.org.hk/en/about-the-collection/) | Printed matter can act as a creative medium and a personal record; use a short ledger and fine rules. | No publication cover, grid, logo or archival image. |
| Editorial / print | [M+ Collection Archives](https://www.mplus.org.hk/en/about-the-collection/m-collection-archives/) | Process documents and ephemera make making visible without turning it into spectacle. | No archive scan, collage or borrowed typographic treatment. |
| Material / spatial | [The Design of the M+ Building](https://www.mplus.org.hk/en/the-building/design/) | Durable material contrast, light wells and porous movement can create atmosphere through structure. | No building silhouette, facade pattern or architectural branding. |
| Contemporary Chinese visual culture | [Hong Kong: Here and Beyond](https://www.mplus.org.hk/en/exhibitions/hong-kong-here-and-beyond/) | Contemporary Chinese visual culture can hold local identity and global modernity together without historical props. | No seals, calligraphy, temple imagery, “ancient” texture or museum identity cues. |
| Digital interaction | [Apple: Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators) | Status must match what is knowable; indeterminate work should not pretend to have a measurable percentage. | No spinner, progress bar or Apple control styling. |
| Digital interaction | [Material Design: Progress indicators](https://m2.material.io/components/progress-indicators) | A status indicator earns its place by reflecting a real operation, not by decorating a wait. | No Material component, colour system or loading animation. |

## Asset provenance and screenshot plan

The field is original inline SVG and CSS authored for this repository. It uses no photographic, licensed, stock or generated asset and has no external request. The five existing palette variables and type roles remain the source of truth.

Browser evidence is planned at 390 × 844: primary slow completion, fast completion, calibration with the history stage omitted, error/abstention with a retry action, and `prefers-reduced-motion`. A 1280px smoke view checks that the field and event ledger retain hierarchy without becoming a dashboard.

Observed evidence is generated by `e2e/qise-postscan-reveal.spec.js` in the local `test-results/` directory. The release audit was run after build and bundle lint; it remains blocked by the repository-wide provenance, commercial-rights, real-device, and store-approval records listed in the handoff, not by this change.

## Scope and overlap

The reveal adds no interpretation, signal, geometry mapping, retention field, network call or dependency. PR #27 changes Qi Se baseline comparison in `src/ui/qise/app.js`; this work keeps that computation intact and places the reveal events around it. If PR #27 lands first, rebase and resolve only the shared `finish()` context, preserving both the baseline changes and the event order.
